# SkyMind Copilot — Evaluation & Quality Assurance Framework

## 1. Evaluation Architecture (`backend/evals/`)

- **Doctor CLI**: `python -m backend.evals.doctor` runs five checks: the Python version, the LangSmith SDK and API key, the OpenAI API key, whether `backend/evals/results` is writable, and whether the configured dataset version and tier load and pass schema validation — plus a normalization spot check that `DEL` and `Delhi` resolve to the same entity. Exit code 0 is healthy, 1 is partial (an optional SDK or key is missing), 2 is a critical failure such as an absent corpus. It does **not** inspect model artifacts or market-provider provenance, and it does not run evaluation scenarios; this list is all of it. The previous wording here — "model artifact integrity, and runs 14+ evaluation test scenarios" — described neither the code nor anything it has ever done.
- **Evaluation Harness**: `python -m backend.evals.run --tier <tier>` loads the golden corpus, runs the planner over every case, and then runs seven self-registered evaluators. Six of them score the **plan**: intent, entities, tool selection, latency, clarification handling, and groundedness. The seventh, `forecast_accuracy`, is the only one whose subject is a forecast — it reads forecasts already resolved against a realised fare out of `forecast_store` and bounds R² (must beat a constant chosen with hindsight), MAPE (ceiling of 15%), and, once a quoted fare is recorded on the forecast row, the improvement over the fare that was already on screen. Without Supabase credentials it reports `INFRASTRUCTURE_UNAVAILABLE`; below 30 resolved forecasts it reports `SKIPPED`, because a bound met on a handful of points is a bound met on noise. Read `overall_success_rate` as a statement about query planning unless `forecast_accuracy` is among the executed evaluators.
- **Honest-by-construction reporting**: a run in which every evaluator skipped is `FAIL`, not a 100% pass; `overall_success_rate` is `None` rather than a number when nothing executed; and a run whose dataset failed its own schema validation is `INVALID` and cannot report `PASS`. Unmeasured headline metrics render as `---` instead of falling back to a perfect value.
- **Tiers**: `smoke` is 6 cases; `full` is all 15, because the loader reads `full` as "every record" rather than as a tag. `--tier nightly` and `--tier regression` are accepted by the CLI but match **zero** records — no golden record carries either tag — so both produce an empty run, which reports `FAIL` / `INVALID`. Adversarial cases are marked with the per-record boolean `regression` (2 of 15), not with a tier.
- **Dataset provenance**: `backend/evals/datasets/v<major>.<minor>/golden.jsonl` is selected by the requested version, and `metadata.json` beside it is cross-checked on every load — a declared record count or version that the corpus contradicts is a schema error, which invalidates the run. A version with no directory loads nothing rather than silently serving whichever corpus is on disk.

## 2. Pytest Automated Suites

- `test_canonical_forecast_v2.py`: 12 component tests over the canonical forecast assembly path — savings calculation, timeline building, the confidence engine, forecast validation, the assembler, and the API mapper. Unit and integration only; nothing here is property-based.
- `test_evals_v2.py`: entity normalization, the registry's full evaluator set, versioned dataset loading with its schema verdict, and one end-to-end smoke run whose success rate is asserted against the evaluator counts beside it.
- `test_evals_resilience.py`: the "a result that could not fail" defect class — a skip is not a pass, the pass ratio uses the executed denominator, groundedness works without an API key and can fail on an invented entity, and the markdown report has no optimistic defaults.
- `test_evals_accuracy.py`: metric arithmetic against hand-worked figures (including that R² is exactly 0.0 for a hindsight constant, which is what the `forecast_accuracy` floor means), `forecast_evaluator`'s coverage reporting, and `ForecastAccuracyEvaluator`'s bounds — among them the case that fails a forecaster inside both absolute bounds which still loses to the fare already on screen.
